# 에셋 제작 규약

이 문서의 규약만 지키면 **코드를 한 줄도 고치지 않고** 모델과 음원을 교체할 수 있다.

교체 절차는 두 단계다.

1. 파일을 `public/assets/` 아래에 넣는다
2. `public/assets/manifest.json` 에 한 줄 추가한다

그 줄을 지우면 프리미티브 도형(또는 무음)으로 되돌아간다. **에셋이 없는 것은 에러가 아니다.**

---

## manifest.json

```json
{
  "models": {
    "yt_infantry":      { "url": "models/yt_infantry.glb", "scale": 1.0, "yOffset": 0, "rotY": 0 },
    "yt_captain":       { "url": "models/yt_captain.glb", "scale": 1.0 },
    "zhangjiao":        { "url": "models/zhangjiao.glb", "scale": 1.0 },
    "hulao_gate":       { "url": "models/hulao_gate.glb", "scale": 1.0 },
    "archer_tower_lv1": { "url": "models/tower_a1.glb" }
  },
  "textures": {
    "path_dirt": "textures/dirt.webp"
  },
  "audio": {
    "sfx_die_small": "audio/die_small.ogg",
    "bgm_level01":   "audio/level01.ogg"
  }
}
```

| 필드      | 의미                                         | 기본값 |
| --------- | -------------------------------------------- | ------ |
| `url`     | `public/assets/` 기준 상대 경로 (또는 절대 URL) | 필수   |
| `scale`   | 모델에 곱해지는 배율                           | `1.0`  |
| `yOffset` | 발바닥이 y=0에 오지 않을 때의 보정             | `0`    |
| `rotY`    | 정면이 +Z가 아닐 때의 보정 (라디안)            | `0`    |

`scale` / `yOffset` / `rotY` 는 보정용 탈출구다. 아래 규약을 지키면 셋 다 필요 없다.
`npm run asset:soldier` 로 구운 모델은 크기와 접지가 이미 들어 있어 `url` 만 적는다.

## 모델 규약

### 단위와 방향

- **1 world unit = 게임 내 1.** 1 타일 = 50 u, 맵은 1200 x 700 u
- **보병 키는 약 34 u** 가 기준. 이 비율을 벗어나면 부감 뷰에서 어색해진다
- **정면은 +Z**, 발바닥이 **y = 0**
- 원점은 발밑 중앙 (모델을 y=0 평면에 세웠을 때 딱 서 있어야 한다)

### 애니메이션 클립명 (고정)

```
idle / walk / attack / die
```

이 네 이름만 인식한다. 다른 이름은 무시되고 그 상태는 정적으로 재생된다.
`die` 는 한 번만 재생되고 마지막 프레임에서 멈춘다 (`clampWhenFinished`).

**뷰가 처음 만들어질 때도 클립이 시작되어야 한다.** `EnemyView` 의 상태 초기값을
`'walk'` 로 두면 생성자의 `playState('walk')` 가 "이미 walk 다"라며 그냥 돌아가서
액션이 시작되지 않는다 — 1파 유닛만 다리가 안 움직이고 미끄러지듯 이동했다.
지금은 초기값이 `null` 이라 반드시 한 번은 재생된다.

클립이 하나도 없으면 프리미티브와 같은 방식(상하 바운스 + 좌우 스웨이)으로
걷는 느낌을 대신 만든다 — **애니메이션 없는 모델을 넣어도 어색하지 않다.**

### 말 탄 기병 — `--body mounted`

다리가 넷이라 사람 뼈대를 그대로 쓸 수 없다. 같은 `rig-model.ts` 를 `--body mounted` 로 돌린다.

```
root ─ body ┬ neck                              말 목·머리
            ├ rider ┬ shoulderL / shoulderR     기수 어깨
            │       └ riderArm                  기수 팔과 무기
            └ legXX ─ kneeXX ─ hoofXX           다리 넷, 각 3마디
```

**다리는 앞뒤(Z)로 먼저 가르고 각각 좌우(X)로 가른다.** 처음엔 하단을 4-means 로 나눴는데
자세에 휘둘렸다 — 앞다리를 든 말(여포의 적토마)에서는 바닥 근처에 뒷다리만 남아
클러스터 넷이 전부 뒷다리 쪽으로 몰렸다. 앞뒤·좌우로 가르면 어떤 자세든 다리 하나씩 잡힌다.
말은 +Z 를 본다고 보므로 Z 가 큰 쪽이 앞다리다.

**다리는 3마디다.** 말 다리는 무릎(앞)·비절(뒤)과 구절에서 두 번 꺾인다.
2마디로 두면 곧은 막대가 흔들리는 것처럼 보인다.
마디 위치는 그 다리 무리의 **실제 최저점**까지를 기준으로 나눈다 —
굽어 든 앞다리는 땅에 닿지 않으므로 바닥을 기준으로 잡으면 뼈가 다리 밖으로 나간다.

**갤럽은 같은 사인파에 위상만 달리 준다.** 네 박자 위상은 뒤 -> 뒤 -> 앞 -> 앞 순이라
뒷다리로 차고 앞다리로 받는 것처럼 보인다. 무릎과 구절은 다리가 **앞으로 나올 때만** 굽고,
구절은 무릎보다 15% 늦게 얕게 따라온다. 뒤로 뻗은 다리를 굽히면 관절이 반대로 꺾여 보이고,
둘이 같이 굽으면 막대가 접히는 것처럼 보인다.

**공격은 말이 아니라 기수가 한다.** 상체(`rider`)는 조금만 숙이고 힘은
어깨(`shoulderL`/`shoulderR`)와 팔(`riderArm`)이 낸다. 상체를 크게 돌리면 말 목 위로 엎어진 것처럼 보인다.
어깨 둘은 **같은 방향**으로 밀어야 두 손으로 잡은 무기가 어긋나지 않는다.

**접지는 걷기 클립 기준이다.** 모든 클립의 최저점으로 잡으면 걷는 내내 떠 있게 되는데,
네 발 짐승이 특히 그렇다(다리를 앞뒤로 뻗으면 몸이 올라간다). 실측으로 기병이 3u 떴고,
걷기 기준으로 바꾸니 0.4u가 됐다. 제자리·공격은 발을 옮기지 않으므로 그 차이만큼만 잠깐 낮게 선다.

### 진영이 달라도 보병 모델은 하나를 쓴다

`xl_infantry`(서량), `ys_infantry`(하북) 는 `yt_infantry` 와 같은 모델을 가리킨다.
5장의 공성 목우와 6장의 목우유마도 같은 수레(`oxcart`) 하나를 쓴다 — 진영만 다른 같은 물건이다.
(화웅·안량은 한동안 `yt_captain` 을 빌려 썼지만 이제 각자 제 모델이 있다.)
매니페스트가 **모델 id -> 파일** 이고 유닛이 그 id 를 가리키는 구조라,
유닛 정의에서 `modelId` 한 줄만 같게 두면 파일이 늘지 않는다.
색이 다른 진영 모델이 생기면 그때 그 유닛의 `modelId` 만 바꾸면 된다.

### 건물은 사람보다 삼각형이 훨씬 많이 필요하다

사람 모델은 2,500~7,000이면 충분한데 건물은 그렇지 않다. 성벽 톱니·창틀·아치처럼
**얇고 각진 구조**가 감면에서 가장 먼저 무너지기 때문이다.

활 망루를 14,000으로 줄였더니 톱니가 부서진 것처럼 뭉개져서 **파괴된 성처럼** 보였다.
원본과 나란히 렌더해 확인한 결과:

| 삼각형 | 결과 |
| ---: | --- |
| 원본 2,000,000 | 기준 |
| 60,000 | 원본과 구분되지 않음 |
| 30,000 | 거의 구분되지 않음 ← **채택** |
| 14,000 | 톱니가 부서진 것처럼 뭉개짐 |

`error`(감면 허용 오차)도 건물은 작게 잡는다(0.005). 목표 삼각형 수와 이 값 중
**먼저 걸리는 쪽**에서 멈추므로, 크게 두면 목표까지 확실히 줄지만 얇은 구조가 먼저 사라진다.
`lockBorder`를 켜면 품질은 좋지만 이 메시(열린 껍질투성이)는 19만 밑으로 내려가지 않는다.

**대가는 삼각형 예산이다.** 만렙 활 망루 5기를 세우면 그림자 패스까지 합쳐 약 50만 삼각형이다
(14,000일 때의 3.5배). 실측 기준 실제 하드웨어에서는 문제 없고, `low` 프리셋은 그림자를 꺼서 절반이 된다.
더 줄여야 하면 `scripts/bake-assets.ts` 의 `tris` 한 줄만 고치면 된다.

**리깅 결과물의 accessor 는 작게 쓴다.** 인덱스는 정점이 65,536 미만이면 16비트,
뼈 번호는 8비트, 가중치는 정규화된 8비트다(전부 0 아니면 1이다).
float32/uint32 로 쓰면 이 셋만으로 파일이 0.6MB 더 커진다.

### 건물 리깅 — 활 망루

사람 모델과 규약은 같지만(크기·접지를 굽는다) 하는 일이 다르다.

```
뼈       tower                  탑 몸체 (움직이지 않는다)
         bow1..bow5             쇠뇌 하나씩
         bow1_nock..bow5_nock   시위를 거는 점
빈 노드  bowN_tipA / bowN_tipB  활 양끝
클립     shoot1..shoot5         쏜 쇠뇌의 것만 재생한다
```

**레벨마다 쇠뇌가 하나씩 는다.** 모델을 레벨별로 따로 두지 않는다 —
하나의 GLTF 안에 쇠뇌가 다섯 개 있고 뷰가 `bowN` 뼈의 스케일로 접는다(0.0001).
메시를 쪼개지 않으므로 드로우콜도 텍스처도 늘지 않는다.

**원본에 쇠뇌가 4개뿐이라 하나를 복제해 탑 가운데에 세운다.** 레벨이 5단계라
5개가 필요하다. 복제본은 정점을 복사하고 뼈 노드의 기본 위치로 옮긴다.

**경계 정점은 부위별로 복제한다.** 한 정점이 탑 삼각형과 쇠뇌 삼각형에 함께 쓰이면,
쇠뇌를 접을 때 그 정점만 한 점으로 빨려 들어가 **가시처럼 늘어난 삼각형**이 남는다.

**시위는 뷰가 그린다.** 원본 메시에서 시위는 실 한 가닥이라 감면하면 사라진다.
그래서 리깅이 활 양끝(`tipA`/`tipB`)과 시위 걸이(`nock`) 위치만 노드로 남기고,
`TowerView` 가 그 셋을 잇는 선을 만들어 매 프레임 갱신한다.
`shootN` 클립이 `nock` 을 뒤로 당겼다 놓으므로 시위가 V자로 당겨졌다 펴진다
(실측 당김폭 0 → 15.9u).

**화살은 그 쇠뇌의 시위에서 떠난다.** 시뮬은 타워 중심에서 쐈다고 계산하지만,
뷰가 `salvoIndex` 로 어느 쇠뇌인지 알아내 `ProjectileView.setLaunch()` 로
실제 발사 지점을 넘긴다. 어긋남은 착탄에 가까워질수록 0이 되므로 명중은 그대로다.

**조준은 쇠뇌만 돈다.** 돌로 지은 탑이 통째로 도는 건 이상하다.
각 쇠뇌는 바인드 포즈에서 바깥(탑 중심 반대)을 보고 있으므로,
그 각도를 기준으로 목표 방향까지의 차이만큼 뼈를 회전시킨다.

### 투석기 리깅 — 벽력거

같은 `rig-tower.ts` 를 `--kind catapult` 로 돌린다. 망루와 다른 점만 적는다.

```
뼈  tower       틀·수레·탄약 더미 (움직이지 않는다)
    bow1        조준 회전(yaw) — 뷰가 목표를 향해 돌린다
    bow1_arm    던지는 각도(pitch) — shoot1 클립이 튕긴다
    bow1_nock   돌이 놓이는 자리 — 여기서 투사체가 떠난다
클립 shoot1
```

**뼈를 두 겹으로 나눈 이유** — 뷰가 매 프레임 `bow1.rotation.y` 를 덮어쓴다.
한 노드에 조준과 발사를 같이 걸면 클립이 지워진다. 그래서 조준은 `bow1`,
발사는 그 자식인 `bow1_arm` 이 맡는다.

**균형추는 팔에 딸려 간다.** 팔은 높이로 갈리지만 균형추 상자는 팔 끝에 매달려
기준선 아래에 있다. 그래서 "**축에서 가까운 쪽** 팔 끝 아래에 있는 것"을 팔에 붙인다.
양쪽 끝에 다 적용하면 던지는 쪽 끝 근처의 탄약 더미까지 딸려가
팔이 젖혀질 때 **돌 하나가 공중에 떠서 날아다닌다**(실제로 그랬다).

**던지는 박자를 시뮬에 맞춘다.** 시뮬은 발사하는 순간 투사체를 만든다.
클립 앞에 젖히는 동작을 두면 돌이 먼저 날아가고 팔이 뒤늦게 따라간다.
그래서 `shoot1` 은 곧바로 던지고(0.07s) 반동으로 젖혀졌다가 제자리로 돌아온다.

**시위는 만들지 않는다.** `TowerView` 는 `bowN_tipA/tipB` 가 있을 때만 시위를 그린다.
투석기는 그 노드를 내보내지 않으므로 활줄이 생기지 않는다.

### 포대 리깅 — 화포 진지

같은 `rig-tower.ts` 를 `--kind cannons` 로 돌린다. 결과 뼈 이름은 활 망루와 같다
(`bowN` / `bowN_nock`) — `TowerView` 의 "레벨만큼만 보여주고 쏜 것만 돌린다" 코드를
그대로 재사용하기 위해서다. 시위가 없으므로 `bowN_tipA/tipB` 는 만들지 않는다.

```
뼈  tower        성벽·데크·정자 (움직이지 않는다)
    bow1..bowN   대포 한 문씩 — 숨기기와 조준 회전, 발사 반동
    bowN_nock    포구 — 포탄과 화염·연기가 여기서 떠난다
클립 shoot1..shootN
```

**대포를 찾는 것이 이 종류의 전부다.** 활 망루는 쇠뇌가 네 귀퉁이에 있어 XZ 사분면으로
갈리지만, 데크가 둥글면 대포가 몇 시 방향에 몇 문 서 있는지 알 수 없다. 높이와 반경만으로도
못 가른다 — 포가는 정자 벽과 같은 반경대에 있다. 그래서 두 단계로 나눈다.

1. **방향 찾기** — 데크에서 난간 밖(`--protrude-r`)으로 나간 것은 포신뿐이다.
   그 삼각형만 1도 히스토그램에 넣고 `--gap-deg` 만큼 비는 곳에서 끊는다.
2. **통째로 가져오기** — 찾은 방향의 부채꼴(±`--sector-pad`)을 통째로 그 대포로 삼는다.
   포가와 바퀴는 난간 안쪽이라 1단계에 안 걸리지만 같은 부채꼴에는 들어온다.

정자가 딸려오지 않는 이유는 정자가 대포와 **다른 방향**에 있기 때문이다
(실측: 대포 16·89·146도, 정자 180~280도).

**임계값은 눈이 아니라 자로 맞춘다.** Y × 반경 점유도를 찍어 보고 정했다.

| 옵션 | 값 | 이렇게 안 하면 |
| --- | --- | --- |
| `--bow-y` | 0.578 | 0.60 은 포가·바퀴를 잘라 데크에 파편을 남기고, 0.565 는 바닥면을 물어 데크에 구멍이 뚫린다 |
| `--deck-top` | 0.74 | 0.72 로 자르면 포신 위 밧줄 장식이 잘려 남는다 |
| `--barrel-lift` | 0.05 | 들려 있는 포구가 천장에 잘린다. 난간 밖이라 정자가 딸려올 걱정은 없다 |
| `--cannon-r` | 0.40 | 데크 한가운데가 딸려온다 |

**반경 기준은 데크의 반경이지 모델 전체가 아니다.** 바닥 지형 슬래브가 데크보다 넓어서,
전체 최대 반경으로 재면 임계값이 통째로 밀려 포신 끝만 잡힌다(실제로 한 문에 80삼각형이었다).

**방향 찾기는 데크 위쪽 70% 만 본다.** 포신은 바닥에 붙어 있지 않다. 바닥 언저리까지 세면
데크 바닥의 단차가 대포로 세어져 **없는 대포가 하나 더 생긴다**(실제로 4문이 나왔다).

**모자란 문수는 돌려서 복제한다.** 원본에는 세 문뿐이라 두 문을 복제해 다섯 문 링을 만든다.
활 망루의 다섯 번째 쇠뇌는 가운데에 세우면 됐지만(`relocate`), 포대의 가운데는 정자가
차지하고 있다. 그래서 복제본은 정점과 노멀을 탑 중심의 Y축 둘레로 **돌려서** 굽는다.
자리는 `bowCount` 문이 고르게 둘러서는 링을 그린 뒤 원본이 차지하지 않은 자리를 쓴다.

### 수레 리깅 — 목우유마 · 공성 목우

바퀴로 굴러가는 탈것은 `rig-cart.ts` 가 맡는다. 사람 뼈대(`rig-model`)를 씌우면
짐칸이 골반·가슴으로 갈려 걸을 때 수레가 휘므로 따로 둔다.

```
뼈    cart              틀·짐칸·소머리·다리 (움직이지 않는다)
      wheelL / wheelR   바퀴 하나씩. 축(X) 둘레로 돈다
클립  idle / walk / attack
```

**바퀴는 RANSAC 으로 찾는다.** 좌우 끝 대역의 정점에 최소제곱으로 원을 맞추면
바큇살과 바퀴통에 정점이 몰려 있어 중심이 안쪽으로 끌려간다(실측: 좌우 중심이
반지름의 20% 어긋났고, 그 중심으로 돌리면 바퀴가 파도치듯 흔들렸다).
세 점의 외접원에 표를 던지면 완전한 원인 테두리에만 표가 몰린다.
두 바퀴는 하나의 축에 꿰여 있으므로 찾은 뒤 중심의 높이와 앞뒤를 평균으로 통일한다.

**바퀴가 헛돌지 않는 이유는 클립 길이에 있다.** `EnemyView` 는 walk 을
`유닛 속도 / 50` 배속으로 돌리므로, 클립 한 번에 한 바퀴를 돌리면 **한 바퀴에
나아가는 거리는 속도와 무관하게 `50 x 클립 길이`** 다. 그 거리를 바퀴 둘레와
같게 두면(`클립 길이 = 2πr / 50`) 감속에 걸려 느려져도 구르는 대로 나아간다.
반지름은 화면 크기라 `units.ts` 의 scale 이 곱해진 값을 쓴다 — 한 모델을 두 유닛이
나눠 쓰면 그 사이값으로 굽는다(목우유마 1.45 / 공성 목우 1.5 -> 1.475).

**공격은 제 몸으로 들이받는다.** 사람은 무기를 내지르지만 수레는 몸이 무기다.
뒤로 물러났다 밀고 들어가 부딪히고 튕겨 나오며, 바퀴도 같이 굴렀다가 뒤로 튄다.
부딪히는 순간은 클립의 53% — `BALANCE.fx.castleAttackImpactAt` 이 거기서 불꽃을 낸다.

### 봉 양 끝에 날이 달린 무기 — `staffBlade`

봉 캡슐의 반경은 **대의 굵기**다. 쌍날 언월도처럼 양 끝이 넓은 무기는 날이 캡슐
밖으로 삐져나가 거리 스키닝이 가져간다. 화웅의 아래 날은 왼 장화 옆에 있어서
**발 뼈**에 붙었고, 걸을 때 날 끝이 다리를 따라 날아갔다(게임 거리에서도 보였다).

켜면 대 굵기의 세 배까지 날로 인정하되 세 가지 제약을 건다.

1. **봉의 양 끝에서만** — 가운데(손 언저리)까지 넓히면 자루가 몸을 가로지르는
   구간이라 갑주와 골반이 통째로 딸려온다(실측: 무기 뼈가 2,410정점을 가져가고
   왼다리에 92개만 남았다).
2. **몸통에서 봉보다 바깥으로 나간 쪽만** — 봉과 몸 사이(장화·갑주 자락)는 몸이 갖는다.
3. **다리 뼈의 살 안쪽은 제외** — 발치에서는 봉 축이 장화 *안*을 지나므로 반경으로는
   못 가른다. 장화는 발 뼈를 감싼 통(중앙값 0.19)이고 날은 그 통 밖(0.23)이라 굵기로 가른다.
   이 제약이 없으면 장화 바닥이 무기에 붙고, 이음매를 자를 때 그 바닥이 떨어져 나가
   **발이 3.6u 뜬 채로 걷는다**(실측).

### 성벽 타격 불꽃

`attack` 클립 중간에 무기가 성벽에 닿는 순간 불꽃이 튄다.
시점은 `BALANCE.fx.castleAttackImpactAt`(클립의 53% 지점)이며,
공격 한 번에 **한 번만** 발생한다(`EnemyView.takeCastleImpact`).

공격 시작에 터뜨리면 무기가 아직 뒤로 젖혀져 있어서 허공에서 불꽃이 난다.
새 무기를 가진 유닛을 넣을 때 클립의 타격 시점이 다르면 이 값을 맞춰야 한다.
불꽃 크기는 유닛의 `scale` 에 비례하고, 보스·장수는 카메라 흔들림이 함께 붙는다.

`attack` 은 적이 성에 닿는 순간 재생된다. 시뮬은 그때 이미 적을 지우고 성에 피해를
주지만, 뷰는 `BALANCE.fx.castleAttackDuration` 동안 남아 창을 한 번 내지르고 사라진다.
클립이 없으면 몸을 통째로 앞으로 내미는 절차적 찌르기로 대신한다.

### 규약에 안 맞는 원본을 받았을 때 — 자동 파이프라인

받은 원본이 규약을 지키지 않는 경우가 실제로 더 흔하다.
첫 리소스(`img/Soldier.glb`)가 그랬다: **200만 삼각형, 8192 텍스처, 61.6 MB,
뼈대 없음, 애니메이션 없음.** 그대로는 못 쓰지만 버릴 것도 아니라
스크립트 두 개로 게임 사양에 맞춘다.

```bash
npm run asset:all          # 원본 세 개를 전부 다시 굽는다
npm run asset:soldier      # 하나만
npm run asset:captain
npm run asset:zhangjiao
```

모델별 기준값(삼각형 수, 팔 구성, 공격 방식, 걸음 주기)은
`scripts/bake-assets.ts` 한 곳에 레시피로 모아 두었다. 긴 명령줄을 손으로 치면
`--arms` 나 `--cadence` 를 빠뜨렸을 때 **조용히 다른 결과가 나오기 때문**이다.

| 모델 | 원본 | 삼각형 | 팔 | 공격 | 걸음 주기 |
| --- | --- | ---: | --- | --- | ---: |
| 황건적 보병 | `Soldier.glb` | 2,500 | single (양손 창) | thrust | 0.9s |
| 황건적 두목 | `Big Soldier.glb` | 6,000 | split (한손 몽둥이) | swing | 1.25s |
| 장각 | `1level_boss.glb` | 7,000 | split (한손 큰칼) | swing | 1.35s |
| 서량 철기 | `Cavalry.glb` | 6,000 | — (말 탄 기병) | 기수가 찌른다 | 0.7s |
| 여포 | `2level_boss.glb` | 9,000 | — (말 탄 기병) | 기수가 찌른다 | 0.8s |
| 화웅 | `화웅.glb` | 7,000 | single (양손 쌍날 언월도) | thrust | 1.12s |
| 목우유마 | `목우유마.glb` | 9,000 | — (바퀴 달린 수레) | 들이받는다 | 굴림 1.47s |
| 활 망루 | `bow_tower.glb` | 30,000 | — (건물) | `shoot1..5` | — |
| 벽력거 | `catapult.glb` | 16,000 | — (건물) | `shoot1` | — |

셋 다 **34u 로 굽는다.** 화면 크기는 `units.ts` 의 `scale` 이 정한다
(보병 1.0, 두목·장각 2.0 → 68u). 모델을 크게 굽는 대신 이렇게 하면
프리미티브 폴백과 크기 비율이 그대로 유지된다.

| 스크립트                    | 하는 일                                                        |
| --------------------------- | -------------------------------------------------------------- |
| `scripts/optimize-model.ts` | weld → 감면(meshopt) → 텍스처 축소 → 정리. 58.8MB → 0.41MB      |
| `scripts/rig-model.ts`      | 사람 형상 — 뼈 11개를 심고 스킨 가중치를 굽고 `idle`/`walk`/`attack` 클립을 만든다 |
| `scripts/rig-tower.ts`      | 건물 — 움직이는 부품을 떼어내 뼈를 심고 `shootN` 클립을 만든다 (`--kind bows\|catapult`) |
| `scripts/rig-cart.ts`       | 수레 — 바퀴를 찾아 뼈를 심고 `idle`/`walk`/`attack` 클립을 만든다 |

```bash
npm run asset:rig -- <in.glb> <out.glb> --forward 0 --height 34
#   --forward  모델이 바라보는 방향(도). +Z가 정면이면 0
#   --height   완성 키(world unit). 보병 기준 34
```

**리깅 방식** — 메시를 분석해(높이, 몸통 중심, 발 클러스터 2-means) 뼈를 놓고,
각 정점을 **뼈 선분까지의 거리**로 가중치 굽는다. 위상으로 부위를 나누지 않는 이유는
받은 메시가 연결 요소 144개로 조각나 있었기 때문이다. 창과 팔은 어느 다리 선분에서도
멀어서 자연스럽게 `chest`로 붙고, 그래서 다리가 흔들려도 창이 찢어지지 않는다.

```
root ─ hips ┬ chest ┬ head
            │       ├ shoulderL / shoulderR   어깨와 위팔
            │       └ arms                    아래팔 + 손 + 창 (한 덩어리)
            ├ legL ─ footL
            └ legR ─ footR
```

**창을 양손으로 잡은 유닛은 팔을 좌우로 나누면 안 된다.** 왼팔·오른팔을 따로 돌리면
한쪽 손이 창에서 떨어진다. 그래서 아래팔·손·창을 `arms` 하나로 묶어 통째로 돌리고,
좌우로 나누는 건 어깨(위팔)까지만 한다. 어깨 회전은 0.1 rad 이하로 두어야
위팔과 아래팔 사이가 벌어지지 않는다.

`arms` 뼈는 **어깨선 바깥에서 시작해야 한다.** 몸통 한가운데에서 시작하면
외투·갑옷까지 이 뼈가 가져가서(실측 774정점) 팔을 조금만 돌려도 상체가 통째로 뒤틀린다.

**미아 정점은 "가장 가까운 뼈"가 받는다.** 고정된 뼈 하나를 fallback 으로 두면
그 뼈가 상체를 통째로 삼킨다. 가장 가까운 뼈로 보내면 외투는 몸통이,
창끝은 팔이 자연스럽게 가져간다.

목표는 해부학적 정확도가 아니라 **45도 부감에서 30~60px로 보일 때 자연스러운 것**이다.
그 크기에서는 손가락 관절이 아니라 실루엣의 상하 움직임과 다리 가위질만 읽힌다.

**크기와 접지는 모델에 구워 넣는다.** 그래서 매니페스트에 `scale`/`yOffset` 을 적지 않는다:

```json
"yt_infantry": { "url": "models/soldier.glb" }
```

손으로 맞춘 보정값은 클립이 바뀌는 순간 어긋난다. 실제로 그렇게 됐다 —
`yOffset` 을 바인드 포즈의 발 높이로 잡았는데, 걷기 클립이 벌린 다리를 모으면서
발이 바인드보다 0.08(모델 단위 = 약 4u) 더 내려가 **걷는 동안 발이 땅에 파묻혔다.**

그래서 리깅 스크립트가 **모든 클립을 CPU에서 실제로 스키닝해** 가장 낮은 정점을 찾고,
그 값을 기준으로 `stand` 노드에 스케일과 평행이동을 건다. 스킨드 메시는 자기 노드의
변환이 무시되므로(관절이 전부 결정한다) 뼈대 루트를 감싸는 노드에 걸어야 한다.

**걷기는 발을 땅에 고정한다(`plantFeet`).** 다리를 앞뒤로 벌리면 다리의 수직 길이가
짧아져 발이 뜨고, 모으면 땅을 뚫는다. IK를 넣는 대신 프레임마다 최저점을 재서
골반 Y를 그만큼 밀어 올린다. 그 결과 몸통의 상하 움직임은 인위적인 bob이 아니라
다리 길이 변화에서 자연스럽게 나온다 — 걷기 클립에 bob 트랙이 없는 이유다.

**애니메이션 translation 은 절대 좌표로 굽는다.** glTF의 translation 채널은 노드의 위치를
*교체*한다(더하지 않는다). 클립은 다루기 쉬우라고 "바인드 위치로부터의 오프셋"으로
만들지만, 굽기 직전에 반드시 절대 좌표로 바꿔야 한다. 이걸 빼먹으면 골반 노드가
바인드 위치가 아니라 오프셋 값으로 순간이동해서 **하반신이 통째로 내려앉는다** —
실제로 발이 지면보다 16u(몸 높이의 절반) 아래로 내려가 다리가 안 보였다.
회전 채널도 절대값이지만 바인드 포즈의 회전이 항등이라 그대로 써도 맞는다.

**가중치는 하드 캡으로 자른다.** 처음엔 부드러운 감쇠(반경 안에서 서서히 약해짐)로
구웠는데, 큰 뼈(hips)가 작은 뼈(다리)를 삼켜서 **다리 정점의 96%가 골반에 붙었고
다리가 통째로 안 움직였다.** 지금은 `maxR` 을 넘으면 후보에서 아예 빠지고,
남은 것 중 가까운 셋을 1/d³ 로 섞는다. 다리 반경은 치마 갑옷 아랫단까지 덮을 만큼
넉넉해야 한다 — 좁게 잡으면 부츠만 움직이고 갑옷과의 이음매가 찢어진다.

**원본은 `img/` 에 그대로 둔다.** 결과만 `public/assets/models/` 로 나가므로,
기준을 바꿔 다시 돌리면 된다. 더 나은(리깅된) 모델이 오면 매니페스트는 그대로 두고
파일만 바꾸면 끝난다.

타워는 레벨마다 다른 모델을 넣을 수도 있지만, 활 망루는 **하나의 모델**을 쓰고
쇠뇌 수로 레벨을 표현한다(위 "건물 리깅" 참고). 매니페스트에서 지우면 프리미티브로 돌아간다.
프리미티브 타워는 지붕 둘레의 활 표식 개수가 곧 화살 수라, 플레이어가 몇 발인지 눈으로 안다.
**GLTF로 교체할 때도 이 정보를 실루엣으로 유지할 것.**

화포 진지도 같은 규약을 따른다 — 모델 하나에 대포 다섯 문이 있고 레벨 수만큼만 보여준다.
다만 **발사 수(1·1·2·2·3)와 포문 수(1~5)는 다르다.** 발사 수는 여섯 장의 밸런스가 얹혀
있는 값이라 연출 때문에 흔들 수 없어서, 대신 `TowerView` 가 일제사격마다 시작 번호를 밀어
다섯 문이 **돌아가며** 쏘게 한다. 5레벨에서 세 발이 나가도 다음 발사는 다음 세 문이 맡는다.

이 포대는 한동안 화공 망루가 쓰고 있었다. 원본(`img/cannon.glb`)이 대포 진지라
5장 화포와 실루엣이 겹쳤고, 그래서 화포 쪽으로 넘겼다. 화공 망루는 불을 다루는
망루로 따로 디자인한다.

## 인물이 둘인 원본 — 하나만 남기기

생성형 3D 원본은 같은 인물을 둘 나란히 세워 한 덩어리로 주는 경우가 있다
(`img/xl_healer.glb`). 그대로 리깅하면 뼈대가 두 사람 사이의 허공에 놓여
팔다리가 엉뚱하게 움직인다. `scripts/isolate-figure.ts` 가 감면 뒤에 하나만 남긴다.

```
npx tsx scripts/isolate-figure.ts <in.glb> <out.glb> --keep max
```

- 정점을 XZ 평면에서 **두 덩어리로 나누고(2-means)** 삼각형을 더 가까운 사람에게 준다.
  평면 하나로 자르면 안 된다 — 두 사람이 비스듬히 서 있을 때 버릴 사람의 봉이
  평면 반대쪽에 남아 발밑에 지팡이 하나가 따로 떠다녔다. 소지품은 주인을 따라가야 한다.
- 남은 인물의 XZ 중심을 원점으로 옮긴다. 안 그러면 유닛이 제 위치에서 비켜서서 걷는다.
- `rotateYDeg` 로 정면을 +Z 로 맞춘다. 파이프라인은 모델이 +Z 를 본다고 전제한다
  (이 승려는 +X 를 보고 서 있어 -90도 돌렸다). 옆을 본 채로 두면 다리가
  진행 방향이 아니라 옆으로 흔들린다.

## 바닥까지 닿는 봉 — `staff: true`

봉·석장처럼 **발끝부터 머리 위까지 이어지는** 무기는 거리 기반 스키닝으로는
다리·골반·가슴·머리 뼈에 토막토막 나뉜다. 그러면 걷기만 해도 봉이 세 동강으로 휜다.
레시피에 `staff: true` 를 주면 `rig-model.ts` 가 이렇게 처리한다.

1. **찾기** — XZ 격자에서 "몸통 축에서 떨어져 있고 키의 90% 이상을 세로로 관통하는"
   기둥을 고른다. 90%가 핵심이다. 60%로 잡았더니 늘어뜨린 장삼 자락(키의 82%)이
   봉(100%)보다 몸에서 더 멀어 그쪽이 뽑혔고, 옷자락이 손에 묶이고 진짜 봉은
   팔 뼈에 붙어 둘이 따로 흔들렸다.
2. **축 맞추기** — 주성분으로 봉의 실제 축을 구해 캡슐로 잡는다. 수직 원기둥으로
   잡으면 조금만 기운 봉도 아래끝이 밖으로 나가 다리 뼈에 붙는다.
   반경은 몸 높이의 7% 로 **고정한다** — 분포에서 다시 재게 했더니 손·소매가 섞이며
   점점 커져 모델의 절반(정점 991개)을 삼켰다.
3. **묶기** — 캡슐 안 정점을 전부 `weapon` 뼈 하나에 100% 로 준다.
   이 뼈의 회전 중심은 **손**이다. 어깨에서 돌리면 봉 아래끝이 반경 1(키만 한 거리)로
   휘둘려 땅을 뚫는다.
4. **접지에서 제외** — 땅에 닿는 기준은 발이다. 봉 끝이 조금 내려갔다고 골반을
   밀어 올리면 유닛이 통째로 뜬다.
5. **클립** — 걷기·제자리에서는 부모(어깨+팔)가 돌린 만큼 정확히 되돌려 봉을 세워 둔다.
   공격(`attackStyle: 'swing'`)은 봉을 손에서 돌린다: 0.25초에 뒤로 세우고(-64도),
   0.4초에 앞아래로 후려친다(+117도). 계측하면 타격 순간 봉 방향이 (z +0.93, y -0.40) —
   앞아래를 향하고, 어느 프레임에서도 지면 아래로 내려가지 않는다.

## 갑주를 두른 덩치 — `bulky: true`

원소(`img/3level_boss.glb`)처럼 넓게 벌린 자세에 갑주를 두른 모델은 날씬한 병사와
전제가 다르다. 레시피에 `bulky: true` 를 주면 세 가지가 켜진다.
날씬한 모델에는 필요 없고 켜면 이미 맞춰 둔 결과가 바뀌므로 기본은 꺼짐이다.

1. **몸통 축을 머리에서 잡는다.** 허리 대역의 중앙값은 몸이 대칭일 때만 몸통 축이다.
   런지 자세에 갑주 자락이 퍼지고 칼 든 팔이 그 높이를 가로지르면 중앙값이 끌려간다
   (실측: 진짜 축 x≈0.05 인데 허리 중앙값 0.162 — 몸 높이의 11%). 그러면 머리 뼈가
   머리 밖에 놓여 정점 2개만 잡는다. 머리에는 무기도 옷자락도 없다.
2. **뼈마다 굵기를 잰다.** 뼈는 선이고 몸은 통이다. 가슴 표면은 척추에서 0.17 떨어져
   있는데 배 앞을 지나는 팔 뼈에는 0.05 까지 붙어서, 거리만으로 재면 팔이 상체를
   통째로 가져간다(실측: armR 1,364정점). 뼈 주변 정점까지의 중앙 거리를 굵기로 빼되
   **옆으로만** 뺀다 — 선분 끝을 넘어서까지 빼면 가슴이 목 위의 머리까지 삼킨다.
3. **팔 뼈가 어깨 바깥에서 시작한다.**

## 갑주 자락 — `skirt`

허리에 매달려 두 다리를 덮는 판이다. 거리로만 굽으면 왼쪽 절반은 왼다리, 오른쪽
절반은 오른다리가 가져가 걸을 때 두 쪽으로 찢어져 판때기처럼 날아다닌다.
`skirt: { toRatio, legInfluence }` 는 허리부터 `toRatio` 높이까지의 다리 가중치를
`legInfluence` 까지만 남기고 골반으로 옮긴다. 아랫단일수록 다리를 조금 탄다 —
완전히 굳히면 그것대로 어색하다.

## 한 손에 든 긴 칼 — `blade: true`

거리 기반 스키닝은 팔에서 뻗어 나간 긴 칼을 팔·가슴·골반 뼈로 토막 낸다.
그러면 걷기만 해도 칼이 활처럼 휜다(장각의 대도가 그랬다). `blade` 를 켜면
칼날을 캡슐로 찾아 **통째로 그 팔 뼈 하나**에 묶는다 — 봉(`staff`)과 같은 장치다.

**아무 모델에나 켜면 안 된다.** 칼날 탐지는 "몸통 축에서 가장 먼 점"에서 축을 맞추므로,
칼이 없는 모델에서는 팔·갑주 자락·장화가 세로로 늘어선 줄을 칼날로 잡는다
(실측: 강동 수병 1.60, 야습대 1.58 — 몸 높이가 1.8인데 그만한 칼은 없다).
그걸 팔 뼈에 통째로 묶으면 **팔을 들 때 다리가 따라 올라간다.**
걸을 때 칼이 휘는 것이 실제로 눈에 보이는 모델에만 켠다.

쌍칼(`dual_swing`)은 양손에 든 것이 둘 다 무기임이 확실하므로 늘 켜져 있다.

## 쌍칼 — `attackStyle: 'dual_swing'`

두 팔이 **함께** 올라갔다가 성벽에 동시에 내리꽂힌다. 한손 무기의 `swing` 과 달리
반대 팔이 균형을 잡지 않고, 몸통도 좌우로 비틀지 않는다(비틀면 한쪽 칼이 앞서 나가
두 팔이 어긋나 보인다).

칼날은 캡슐로 찾아 그 팔 뼈에 통째로 묶는다. 여기까지 오면서 버린 방법들:

| 방법 | 왜 실패했나 |
| --- | --- |
| 좌우 상체를 통째로 팔에 묶기 | 갑주가 두꺼워 가슴 갑옷까지 팔을 따라 돌았다 |
| 연결 요소로 묶기 | 감면이 표면을 86조각으로 쪼개 칼이 한 조각이 아니다 |
| 팔 덩어리에 주성분 맞추기 | 칼날은 정점이 적어 어깨갑옷 덩어리가 축을 가져간다 |
| 팔 뼈를 칼끝까지 늘리기 | 내린 칼은 가슴보다 아래라 팔 덩어리에 안 들어온다 |

캡슐은 칼끝(몸통 축에서 가장 먼 정점)에서 시작해 축을 다듬고, **칼끝에서 몸 쪽으로
걸어 들어가며** 길이를 잰다 — 축을 따라 얇게 썰면 칼 구간은 단면이 몇 개뿐이고 몸에
닿는 순간 불어나므로 거기서 멈춘다. 투구와 그 장식(머리 위 좁은 원기둥)은 칼로 보지
않는다. 그러지 않으면 칼날 축이 그 옆을 스치며 투구 절반을 물어, 휘두를 때 검은
판때기로 늘어난다.

### 배경음은 매니페스트에 없다

곡 파일은 하나가 수 MB라 우리가 서빙하면 접속자 수만큼 트래픽이 나간다.

곡을 바꾸려면 레벨 정의의 `environment.bgmYoutubeId`에 영상 id만 바꿔 넣으면 된다.

| 레벨 | 필드                  | 현재 값       |
| ---- | --------------------- | ------------- |
| 1장  | `LEVEL_01.environment.bgmYoutubeId` | `zYY4gbajgKY` |
| 2장  | `LEVEL_02.environment.bgmYoutubeId` | `9KxUmZ4v2HI` |
| 3장  | `LEVEL_03.environment.bgmYoutubeId` | `Z-HHzu3rhj8` |

- 레벨에 들어가면 자동 재생되고 그 레벨이 끝날 때까지 반복된다
- 하단 바의 `♪` 버튼 하나로 켜고 끈다 (상태는 다른 오디오 설정과 함께 저장된다)

## 새로 쓰는 음원 id

| `sfx_cannon`                | `cannon.mp3`       | 화포 진지 발사, 그리고 성문의 대포 일제사격 |

성벽 타격음은 유닛 id가 아니라 **종류(kind)** 로 고른다(`SOUND_MAP['enemy:castle-attack']`).
진영을 새로 추가해도 표를 고칠 필요가 없고, 특정 유닛만 다른 소리를 내야 할 때만
그 유닛 id를 한 줄 더 적으면 된다(id 쪽이 먼저 잡힌다).

성문의 포성은 발사 한 발마다가 아니라 **일제사격 한 번에 한 번** 난다
(`castle:fired` 이벤트). 4발 연사에서 굉음이 네 번 겹치면 포성이 아니라 잡음이 되기 때문이다.

## 말 탄 장수의 공격 — 찌르기와 휘두르기

`bodyKind: 'mounted'` 도 `attackStyle` 을 따른다.

| attackStyle | 무엇                                       | 쓰는 곳            |
| ----------- | ------------------------------------------ | ------------------ |
| `thrust`    | 창을 앞으로 내지른다                       | 서량 철기(cavalry) |
| `swing`     | 어깨·몸통이 가로로 돌며 무기를 후려친다    | 여포(lubu)         |

**날이 옆으로 뻗은 무기는 반드시 `swing` 이어야 한다.** 여포를 기본값(찌르기)으로
구웠더니 앞으로 나가는 성분밖에 없어서, 화면에서는 방천화극이 아니라
**머리로 들이받는 것처럼** 보였다. 찌르기 클립은 말 목(neck)까지 흔들어서
그 인상을 더 강하게 만들었다.

`swing` 이 다르게 하는 것 셋:

1. **몸통을 앞으로 거의 내보내지 않는다.** 앞으로 나가면 다시 들이받는 그림이 된다.
2. **가로 성분(yaw)을 섞는다.** 팔·어깨·기수 상체가 모두 Y축으로도 돈다 —
   오른쪽 위에서 왼쪽 앞아래로 가로지르는 궤적이 있어야 "휘둘렀다"로 읽힌다.
3. **말 목은 건드리지 않는다.** 말은 버티고 서 있고 움직이는 것은 기수여야 한다.

동작은 다섯 마디다 — 준비 / 젖힘 / **정점에서 정지** / 내리침 / 복귀.
정점의 정지가 없으면 "들었다 내렸다"만 보이고 무게가 실리지 않는다.

검증은 두 군데서 한다. `tests/castleAttack.test.ts` 가 클립 데이터를 직접 뜯어
가로 성분과 팔 회전량을 확인하고, `scripts/_verify-lubu.ts` 가 구운 GLB를
브라우저에서 재생해 무기 끝의 실제 궤적을 잰다.
