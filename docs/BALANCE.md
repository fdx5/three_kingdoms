# 밸런스

모든 밸런스 수치는 `src/data/` 안에만 있다. 다른 곳의 매직넘버는 버그다.

| 파일                        | 무엇                                     |
| --------------------------- | ---------------------------------------- |
| `src/data/balance.ts`       | 전역 상수 (웨이브 간격, 조기소집 계수, 연출 시간, 성능 프리셋) |
| `src/data/units.ts`         | 적 스탯 (황건적)                         |
| `src/data/unitsXiliang.ts`  | 적 스탯 (서량군 — 레벨 2)                |
| `src/data/unitsYuan.ts`     | 적 스탯 (하북군 — 레벨 3)                |
| `src/data/towers.ts`        | 타워 레벨 표 (해금 레벨 `unlockedIn` 포함) |
| `src/data/stratagems.ts`    | 계략 카드 (비용·쿨다운·효과)             |
| `src/data/waves.ts`         | 웨이브 생성기 (하드코딩된 웨이브는 없다) |
| `src/data/levels/levelNN.ts`| 경로, 건설 슬롯, 웨이브 파라미터, 환경색 |

## 레벨 1 확정 수치

```
경제   시작골드 500 / 보병처치 10G / 중간보스 200G / 최종보스 500G
성     체력 1000, 보병 도달 -20, 보스 도달 -100 (도달한 적은 즉시 소멸)
적     보병 HP 20, 속도 50 u/s. 웨이브마다 HP x1.14, 속도 x1.02 누적
       중간보스(10파) HP 500 고정, 크기 2배
       최종보스(20파) HP 1000 고정
웨이브 n번째 보병 수 = 10 + 2*(n-1)  (1파 10기 ~ 20파 48기, 총 580기)
       스폰 간격 = max(0.40, 1.10 - 0.03n) 초
건설   경로변 고정 슬롯 5개, 궁노 망루 건설비 100G
```

**보스는 성장 배율을 받지 않는다.** `generateWaves` 의 `inserts` 로 들어간 유닛은
`hpMul`/`speedMul` 이 1이다. 성장시키면 20파에서 HP가 16,000이 된다.

| Lv | 화살 | 피해 | 간격  | DPS  | 비용     | 누적 투자 |
| -- | ---- | ---- | ----- | ---- | -------- | --------- |
| 1  | 1    | 10   | 1.00s | 10   | 100 (건설) | 100     |
| 2  | 2    | 13   | 0.95s | 27   | 100      | 200       |
| 3  | 3    | 17   | 0.90s | 57   | 150      | 350       |
| 4  | 4    | 22   | 0.85s | 104  | 200      | 550       |
| 5  | 5    | 28   | 0.80s | 175  | 250      | 800       |

판매 시 누적 투자액의 70% 환급 (만렙 800G → 560G).
사거리는 5레벨 전부 100u — 사거리 증가는 향후 다른 타워의 차별점으로 남겨두었다.

### 화살 배분 규칙 — 밸런스의 핵심

사거리 안의 적을 `targeting` 순으로 정렬한 배열을 `T`, 화살 수를 `L` 이라 할 때

```
i번째 화살(i = 0..L-1)의 목표 = T[i]   (T의 길이를 넘으면 T[0])
```

즉 **서로 다른 적에게 분산 발사하고, 적이 모자랄 때만 선두 적에게 겹친다.**

한 마리에 몰아 쏘면 HP 20 보병에게 화살 5발이 낭비되어 업그레이드가 전혀 체감되지 않는다.
이 규칙을 바꾸면 레벨 1의 학습 목표(업그레이드)가 통째로 무너진다.
`tests/sim.test.ts` 의 "화살 배분 규칙" 블록이 이걸 지킨다.

## `npm run sim` — 헤드리스 밸런스 러너

three 없이 20웨이브를 끝까지 돌려 표를 출력한다. 렌더가 없으므로 몇백 ms면 끝난다.

```bash
npm run sim                                   # 레벨 1, 5기 건설 + 적극 업그레이드
npm run sim -- --towers 3 --upgrade greedy    # 좋은 자리 3기만
npm run sim -- --towers 5 --upgrade none      # 업그레이드 안 함
npm run sim -- --slots d,e,a                  # 슬롯 직접 지정 (배치 실패 재현)
npm run sim -- --level 2                      # 레벨 2 (3종 혼합 자동 배치)
npm run sim -- --level 2 --build archer       # 전부 궁노 — 속성을 무시했을 때
npm run sim -- --level 2 --no-repair          # 성벽 수리의 값을 측정
npm run sim -- --level 2 --cards boss         # 계략을 장수에게 아껴 쓴다
npm run sim -- --level 2 --cards greedy       # 계략을 쓸 만하면 바로 쓴다
npm run sim -- --seed 42
```

| 옵션            | 값                | 뜻                                        |
| --------------- | ----------------- | ----------------------------------------- |
| `--level`       | `1` / `2` / id    | 돌릴 레벨 (기본 level01)                  |
| `--towers`      | 정수              | 커버리지가 높은 슬롯부터 이만큼 짓는다    |
| `--slots`       | `a,b,c`           | 슬롯을 직접 지정 (`slot_` 접두사 생략 가능) |
| `--build`       | `auto` / `archer` / id 나열 | `auto`=좋은 자리 궁노·기병 직선 질려·나머지 벽력거 |
| `--upgrade`     | `greedy` / `none` | 여유 골드가 생기면 항상 올릴지            |
| `--no-repair`   | —                 | 성벽 수리를 하지 않는다                   |
| `--cards`       | `none`/`greedy`/`boss` | 계략 사용 정책 (기본 none)           |
| `--early`       | —                 | 대기 중이면 항상 조기 소집 (레벨 3의 권장 플레이) |
| `--focus-healer`| —                 | 도사를 먼저 노리도록 타게팅을 바꾼다      |
| `--seed`        | 정수              | 난수 시드 (같은 시드 = 같은 결과)         |

출력은 웨이브별 표(적 수 / 보병 HP / 종료 골드 / 성 체력 / 누수)와 최종 결과다.

`tests/sim.test.ts` 가 매번 확인하는 값들이다.

| 플레이 방식                        | 결과       | 남은 성 체력 | 누수 |
| ---------------------------------- | ---------- | -----------: | ---: |
| 슬롯 5개 전부 + 적극 업그레이드    | 승리       |    1000/1000 |    0 |
| 모퉁이 3기(a·b·c) + 업그레이드     | 승리       |    1000/1000 |    0 |
| 직선 위주 3기(d·e·a) + 업그레이드  | 승리       |     700/1000 |   11 |

**해석** — 업그레이드를 하면 배치가 나빠도 이기고, 안 하면 중간보스가 나오는
10웨이브에서 반드시 진다. 배치는 승패가 아니라 별 등급을 가른다.
레벨 1이 가르쳐야 할 것이 정확히 하나(업그레이드)라는 뜻이고, 튜토리얼 레벨로서 올바른 형태다.

### 총량

- 20웨이브 총 보병 **580기** (+ 보스 2기)
- 획득 가능 총 골드 **7,000 G** (보병 5,800 + 보스 700 + 시작 500)
- 타워 5기 만렙 비용 **4,000 G**
- 잉여 골드 **3,000 G (43%)** → 레벨 2에서 성벽 수리로 흡수한다 (아래)
- 패배까지 허용 누수: 보병 **50기** (전체의 8.6%)

남는 골드를 쓸 곳이 없다는 문제는 레벨 1에서는 **별 등급**으로 흡수한다
(성 체력 100% = 3별, 70% 이상 = 2별, 그 외 1별).

## 레벨 2 확정 수치

레벨 1이 가르친 것은 "업그레이드" 하나였다. 레벨 2가 가르치는 것은
**속성에는 답이 따로 있다**이다. 그래서 성 체력을 1000 → 600으로 낮췄다.
누수가 실제 위협이 되어야 답을 찾을 이유가 생긴다.

```
경제   시작골드 600 / 획득 가능 총 골드 10,192 G
성     체력 600, 보병 도달 -18 ~ -30, 여포 도달 -160
웨이브 n번째 9 + 2*(n-1) 기 (총 562기), 간격 18초, 첫 웨이브 24초 후
       스폰 간격 = max(0.38, 1.05 - 0.03n) 초, HP x1.13 / 속도 x1.015 누적
건설   경로변 고정 슬롯 6개, 타워 3종
소비처 성벽 수리(4G당 1HP) + 계략 3종(260~450 G)
별     성 체력 60% 이상 3별, 35% 이상 2별
```

**웨이브 간격 18초는 임의가 아니다.** 레벨 1의 12초를 그대로 쓰면 후반에
웨이브 3개가 동시에 경로 위에 올라가 최선의 플레이도 성 체력 24%로 끝난다(실측).

### 서량군 — 속성마다 답이 다르다

| 적 | HP | 속도 | 속성 | 답 |
| --- | ---: | ---: | --- | --- |
| 서량 보병 | 34 | 50 | — | 아무 타워나 |
| 서량 철기 (4파~) | 26 | 112 | 빠르다 | **철질려** — 사거리 안 체류 시간을 늘린다 |
| 서량 방패병 (7파~) | 90 | 38 | 원거리 저항 72% | **벽력거** — 공성 피해는 저항을 무시한다 |
| 종군 도사 (11파~) | 70 | 44 | 반경 90 안을 초당 14 회복 | **타게팅** — 선두 말고 도사를 먼저 끊는다 |
| 화웅 (10파) | 950 | 46 | 원거리 저항 25% | 벽력거 |
| 여포 (20파) | 2400 | 44 | 저항 30%, 8초마다 3초간 속도 x2.6 | 벽력거 + 감속으로 묶기 |

**벽력거는 레벨이 올라도 발사체가 1개다.** 궁노의 N발은 서로 다른 적에게 흩어지므로
HP 2400짜리 여포에게는 5발 중 1발만 꽂힌다. 한 발에 몰아주는 타워가 있어야
방패병과 장수 양쪽의 답이 된다. 실제로 벽력거를 2발로 두었더니 여포가 매번 성에 닿았다.

**철질려의 감속은 진지 밖까지 이어져야 한다.** 지속 시간이 짧으면 사거리를 벗어나는
순간 원래 속도로 돌아가 "뒤에 있는 망루에 시간을 벌어준다"가 성립하지 않는다.
실측: 0.55배 1.2초로는 슬롯 하나 값을 못 했다(누수 21, 미설치 13보다 나쁨).
현재 값은 **0.42배 2.6초**다.

### 성벽 수리 — 골드 소비처

```
4 G당 1 HP, 한 번에 50 HP, 쿨다운 8초, 웨이브 스폰 중에는 불가
```

세 제약이 전부 필요하다. 상시 수리(2G/HP)를 허용했더니 누수 36기를 내고도
600/600으로 끝났다 — 방어 실패가 무료로 지워졌다. 쿨다운이 없으면 골드가 있는 한
매 프레임 고칠 수 있어 결과는 같다. 지금 값은 "보병 3~4기를 잡아야 누수 1기를
되돌린다"는 환율이라, 잉여 골드를 흡수하되 실패를 지워주지는 않는다.

### 계략 — 웨이브 한복판의 골드 소비처

수리는 웨이브 사이에만 쓸 수 있어서, 남는 골드를 다 흡수하지 못했다
(권장 조합으로 끝까지 가도 3,000 G가 남았다). 계략은 그 나머지를 가져간다.

| 계략 | 비용 | 쿨다운 | 효과 |
| --- | ---: | ---: | --- |
| 매복 (伏) | 260 G | 30초 | 모든 적 속도 x0.45, 4초 |
| 화공 (火) | 400 G | 30초 | 모든 적에게 공성 피해 45 |
| 원군 (援) | 450 G | 35초 | 모든 타워 피해량 x1.5, 10초 |

**쿨다운이 아니라 골드가 한계여야 한다.** 처음엔 쿨다운을 45~80초로 두었는데,
그러면 보스 웨이브 한 번에 각 카드를 한 장씩밖에 못 써서 골드가 다시 남았다
(계략에 960 G 쓰고 2,156 G 잔여). 30초로 줄이자 큰 웨이브에서 연달아 쓰게 되어
2,200~3,200 G가 흡수된다. 소비처의 목적은 골드를 가져가는 것이다.

**화공 45는 방패병(HP 90)을 한 방에 못 죽이는 값이다.** 여기를 넘기면
계략이 벽력거를 대신하게 되고 레벨 2의 교훈이 사라진다.
`tests/level02.test.ts` 가 이 부등식과 "계략을 써도 전부 궁노로는 못 이긴다"를 지킨다.

**즉발 계략은 대상이 없으면 발동 자체가 막힌다.** 빈 경로에 화공을 쓰면
골드만 사라지는데, 그건 실수지 선택이 아니다. 지속형(원군)은 미리 걸 수 있다.

### 검증된 결과 (레벨 2)

`tests/level02.test.ts` 와 `npm run sim -- --level 2` 가 확인하는 값들이다.

| 플레이 방식 | 결과 | 남은 성 체력 | 누수 |
| --- | --- | ---: | ---: |
| 6슬롯 3종 혼합 + 업그레이드 + 수리 | 승리 | 288/600 (48%) | 11 |
| 6슬롯 3종 혼합 + 업그레이드, 수리 안 함 | 승리 | 188/600 (31%) | 11 |
| 6슬롯 **전부 궁노** + 업그레이드 + 수리 | 20파 패배 | 0 | 42 |
| 6슬롯 전부 궁노 + 업그레이드, 수리 안 함 | 19파 패배 | 0 | 20 |
| 좋은 자리 3슬롯만 궁노 + 업그레이드 + 수리 | 18파 패배 | 0 | 47 |
| 6슬롯 3종 혼합 + 수리, **업그레이드 안 함** | 12파 패배 | 0 | 33 |
| 위 권장 조합 + 계략을 **장수에게 아껴 씀** | 승리 | 510/600 (85%) | 4 |
| 위 권장 조합 + 계략을 **헤프게 씀** | 승리 | 390/600 (65%) | 6 |
| 전부 궁노 + 계략을 아껴 씀 | 20파 패배 | 0 | 38 |
| 전부 궁노 + 계략을 헤프게 씀 | 20파 패배 | 0 | 28 |

**해석** — 전부 궁노로 채우면 20파까지는 가지만 방패병에 막혀 반드시 진다
(패배 누수 42기 중 39기가 방패병이다). 슬롯 수도 타워 등급도 아닌 **종류**가 승패를
가르는 첫 레벨이고, 이게 레벨 2의 학습 목표와 정확히 일치한다.

수리는 승패를 뒤집지 않고 등급만 올린다(31% → 48%). 골드 소비처로서는 이게 맞다 —
이겼어야 할 판을 이기게 해주면 그건 소비처가 아니라 두 번째 성 체력이다.

계략도 같다. **져야 할 판(전부 궁노)은 계략을 어떻게 써도 여전히 진다.**
바뀌는 것은 등급이다: 안 쓰면 48%(2별), 헤프게 쓰면 65%, 장수에게 아껴 쓰면 85%.
3별(60%)은 남는 골드를 언제 쓸지 아는 사람이 가져간다 — 그게 레벨 2의 세 번째 별이다.

**아껴 쓰는 쪽이 더 낫다는 것이 중요하다.** 두 정책의 차이(85% vs 65%)가
계략에 판단이 들어갈 여지를 만든다. 쿨다운이 돌 때마다 누르는 게 최선이면
그건 선택지가 아니라 그냥 자동 버튼이다.

`npm run sim -- --level 2 --cards boss|greedy|none` 으로 세 정책을 각각 돌려볼 수 있다.
`boss` 는 장수가 경로에 있을 때만, `greedy` 는 적 체력 합이 기준을 넘으면 바로 쓴다.

## 레벨 3 확정 수치

레벨 1은 **성장**, 레벨 2는 **조합**을 가르쳤다. 레벨 3이 가르치는 것은 **시간**이다.

```
경제   시작골드 450 / 처치 골드 상한 5,930 G / 권장 조합 비용 7,000 G
       -> 1,070 G 가 구조적으로 모자란다. 조기 소집으로 앞당겨 벌어야 한다.
조기소집 남은 대기 1초당 10 G (레벨 1·2는 4 G). 15초를 통째로 당기면 150 G
성     체력 500, 보병 도달 -14 ~ -22, 원소 도달 -150
웨이브 n번째 12 + 2*(n-1) 기 (총 622기), 간격 15초, 첫 웨이브 22초 후
건설   경로변 고정 슬롯 7개 (좋은 자리 3 : 나쁜 자리 4)
소비처 성벽 수리만. **계략은 열지 않는다**
별     성 체력 60% 이상 3별, 35% 이상 2별
```

**모자란 골드가 이 레벨의 설계다.** 처치 골드만으로는 권장 조합(궁노 3 + 벽력 3 +
철질려 1 = 7,000 G)을 완성할 수 없다. 부족분은 웨이브를 앞당겨 메우는데,
당긴 웨이브는 앞 웨이브와 겹쳐서 오므로 그건 공짜 돈이 아니라
"지금 방어선이 이만큼은 감당한다"에 거는 돈이다.
`tests/level03.test.ts` 가 이 부등식(처치 골드 < 필요 비용 < 처치 골드 + 조기 소집 상한)을 지킨다.

**계략을 열지 않은 이유.** 레벨 2는 잉여 골드가 문제라 소비처가 답이었다.
레벨 3은 정반대로 골드가 모자란 것이 문제다. 여기에 소비처를 더 두면
카드 한 장이 곧 타워 한 기가 되어 함정이 된다 — 실측으로 계략을 쓰면
성 체력이 236에서 66으로 떨어졌다. 같은 물건도 레벨의 문제가 다르면 값이 달라진다.

### 하북군 — 물량과 속도

| 적 | HP | 속도 | 속성 | 답 |
| --- | ---: | ---: | --- | --- |
| 하북 보병 | 46 | 54 | — | 아무 타워나 |
| 하북 창병 (5파~) | 130 | 44 | 원거리 저항 30%, 두껍다 | 벽력거 |
| 하북 기수 (8파~) | 70 | 50 | 반경 110 아군 속도 **x1.45** | 먼저 끊는다 |
| 안량 (10파) | 1700 | 46 | 저항 35% | 벽력거 |
| 원소 (20파) | 2800 | 42 | 저항 35%, 반경 200 아군 속도 **x1.35** | 벽력거 + 감속 |

**가속 오라는 회복 오라의 반대편이다.** 도사(레벨 2)가 "더 안 죽는다"였다면
기수는 "더 빨리 온다"다. 방어선을 지나는 시간을 줄이므로, 끊지 않으면
웨이브 전체가 앞당겨 도착한다 — 조기 소집을 스스로 당한 것과 같다.

가속은 감속과 **곱해진다.** 철질려에 걸린 기수 부대는 느려진 채로 조금 빨라질 뿐이라,
감속 타워가 무효가 되지 않는다 (`tests/level03.test.ts`가 이 곱셈을 지킨다).

### 검증된 결과 (레벨 3)

| 플레이 방식 | 결과 | 남은 성 체력 | 누수 |
| --- | --- | ---: | ---: |
| 전 슬롯 + 업그레이드 + **조기 소집** + 수리 | 승리 | 236/500 (47%) | 20 |
| 위와 같되 **조기 소집을 안 함** | 9파 패배 | 0 | 28 |
| 조기 소집 + 전 슬롯, 수리 안 함 | 승리 | 32/500 (6%) | 20 |
| 조기 소집, 슬롯 4개만 | 20파 패배 | 0 | 33 |
| 조기 소집, **업그레이드 안 함** | 11파 패배 | 0 | 34 |
| 조기 소집, **전부 궁노** | 20파 패배 | 0 | 27 |

**해석** — 조기 소집 하나가 9파 패배와 승리를 가른다. 그게 이 레벨의 교훈이다.
동시에 앞 두 레벨의 교훈도 그대로 살아 있다: 업그레이드를 안 하면 11파에서 죽고,
전부 궁노면 창병(누수 26/27)에 막혀 20파에서 죽는다.
**레벨이 쌓여도 앞에서 배운 것이 무효가 되지 않아야 한다** — 그게 세 레벨을 관통하는 기준이다.

```bash
npm run sim -- --level 3 --early     # 조기 소집을 매번 쓴다 (권장 플레이)
npm run sim -- --level 3             # 안 쓴다 — 9파에서 무너지는 걸 볼 수 있다
```

## 맵 설계 기준

건설 슬롯의 가치는 "사거리 100 안에 들어오는 경로 길이"로 정의된다.
`tests/data.test.ts` 가 실제로 계산해 출력한다.

```
레벨 1  slot_a=380u  slot_b=380u  slot_c=380u  slot_d=143u  slot_e=132u
레벨 2  s2_a=377u  s2_b=430u  s2_c=430u  s2_d=143u  s2_e=143u  s2_f=160u
레벨 3  s3_a=409u  s3_b=320u  s3_c=320u  s3_d=240u  s3_e=160u  s3_f=120u  s3_g=143u
```

- `slot_a/b/c`, `s2_a/b/c` 는 **헤어핀(U턴) 안쪽**이다. 두 평행 구간(간격 120u)과
  연결부를 동시에 덮어 380~430u — 좋은 자리
- `slot_d/e`, `s2_d/e/f` 는 직선 구간 옆이라 한 구간만 덮어 140~160u — 나쁜 자리

레벨 2는 좋은 자리 3 : 나쁜 자리 3으로 두었다. 타워가 3종이 되면서
"어디에" 뿐 아니라 "무엇을"이 같이 문제가 되어야 하기 때문이다 —
나쁜 자리라도 기병 직선 옆이면 철질려의 값이 완전히 달라진다.

**직각 모퉁이(L자)는 이론상 최대 약 283u까지밖에 못 덮는다.** 300u를 넘기려면
경로가 되돌아오는 헤어핀이어야 한다. 새 맵을 만들 때 이 사실을 기억할 것 —
테스트는 최소 3개 슬롯이 300u 이상을 덮을 것을 요구한다.

## 수치를 바꿀 때

1. `src/data/` 의 값을 고친다
2. `npm test` — 데이터 무결성과 밸런스 시나리오가 따라 움직이는지 본다
3. `npm run sim` — 웨이브별 표로 어디서 무너지는지 본다
4. `npm run dev` — 실제 감각을 확인한다

2번과 3번을 건너뛰고 4번만 하면, 그 시점부터 수치 조정이 전부 추측이 된다.

## 레벨 4~6 실측 (2026-09-05)

`npm run sim -- --level N` 기준. 배치는 `auto`(커버리지 상위 두 자리에 궁노·화공,
경로 앞쪽 나쁜 자리에 철질려, 사거리 175 커버리지가 큰 자리부터 화포, 나머지 벽력거),
업그레이드 greedy, 수리 on, 계략 none, 성문 `after`(타워를 다 세운 뒤 남는 돈으로).

| 레벨 | 권장 조합            | 성문 없이            | 궁노 도배      |
| ---- | -------------------- | -------------------- | -------------- |
| 4    | 승리 990/1020 · 누수 12 · 성문 Lv5 | **6파 패배**   | 6파 패배 (누수 111) |
| 5    | 승리 998/1120 · 누수 71 · 성문 Lv4 | 승리 266/800   | 7파 패배 (누수 101) |
| 6    | 승리 1360/1360 · 누수 12 · 성문 Lv6 | **14파 패배**  | 11파 패배 (누수 59) |

읽는 법:

- **4장과 6장은 성문이 필수다.** 같은 타워·같은 업그레이드 정책으로 성문만 빼면 진다.
  4장은 슬롯 다섯의 커버리지가 전부 300u 미만이라 성 앞이 비고, 6장은 목우유마가
  성문 앞에 모여 서로를 회복시켜 1단계 성문(초당 40)으로는 영영 죽지 않는다.
- **5장은 성문이 필수가 아니다.** 여기서 필수인 것은 화포다. 성문을 안 올려도 이기지만
  성 체력이 998에서 266으로 떨어진다 — 등급이 갈리는 자리다.
- **세 장 모두 궁노 도배는 진다.** 4장은 등갑(원거리 저항 65%), 5장은 대도수(50%)와
  목우(35%), 6장은 백이병(38%)이 각각 그 벌을 준다.

성문 강화는 총 4,200 G다. 만렙 화포 진지(1,590 G) 두 기하고도 남는 값이라,
"슬롯이 모자라는 마지막 구간을 살 때만" 이득이 되게 잡혀 있다.

### 왜 성문 값을 재려면 누수로 재야 하는가

타워를 한 기도 짓지 않고 레벨 4를 120초 돌린 결과다.

| 성문 | 발사 | 처치 | 누수 | 성 체력 |
| ---- | ---: | ---: | ---: | ------- |
| Lv1  | 210  | 21   | 35   | 547/700 |
| Lv2  | 396  | 33   | 33   | 657/750 |
| Lv3  |  24  | 35   | 0    | 만피    |
| Lv6  |  18  | 35   | 0    | 만피    |

발사 수로 재면 거꾸로 나온다 — 강한 성문은 적을 먼저 지워서 쏠 대상이 사라진다.
처치 수도 사거리 안 적을 전부 잡는 순간 포화된다. **누수만이 "막았는가"를 그대로 나타낸다.**

## 성벽 타격 주기 — 장수는 2초, 잡몹은 16초

`BALANCE.castleCombat` 한 곳에 있고 **모든 장에 같이** 적용된다(레벨이 덮어쓰지 않는다).

| 대상             | 간격 | 한 대의 세기 (castleDamage 대비) | 초당 |
| ---------------- | ---: | -------------------------------: | ---: |
| 잡몹 (minion)    | 16초 | 0.20                             | 0.0125 |
| 장수 (elite/boss) |  2초 | 0.025                            | 0.0125 |

**왜 세기를 8분의 1로 나눴는가.** 간격만 8배 짧게 하고 세기를 그대로 두면
여포 한 기가 초당 16씩 깎아 2장 성(600)을 40초에 무너뜨린다 — 막을 수 있는
위협이 아니라 도달하는 순간 끝나는 판정이 된다. 실측으로 **3장과 5장이 그 자리에서
패배로 뒤집혔다**(3장 14파, 5장 12파). 0.20/8 = 0.025 로 두면 초당 피해가
예전과 정확히 같아, 여섯 장의 밸런스를 그대로 두면서
"장수가 쉬지 않고 성벽을 친다"만 얻는다.

바뀐 것은 **체감**이다. 16초 간격에서 장수는 대개 두 번째 타격 전에 죽어서
성문 앞에 그냥 서 있는 것처럼 보였다. 2초면 서 있는 동안 계속 때리므로
"장수를 성문까지 보내면 안 된다"가 실제로 눈에 보이는 규칙이 된다.

장수를 더 사납게 하려면 `bossStrikeDamageMul` 하나만 올리면 된다. 참고로
0.03 에서 3장이 250/500 -> 125/500 이 되고, 0.055 에서는 3·5장이 패배한다.

뷰도 같은 주기로 돈다. 공격 클립을 기본값(LoopRepeat)으로 두면 클립이 제 길이
(0.75~0.95초)마다 계속 돌아서, 성이 안 깎이는데도 쉬지 않고 휘두르는 그림이 된다.
`EnemyView.startCastleAttack(interval)` 이 타격 주기를 받아 그 박자로만 다시 재생한다.

## 난이도 손잡이 — 웨이브 성장 가산치와 장수 배율 (2026-09-08)

"전체적으로 너무 쉽다"에 대한 답. 여섯 장의 표를 다시 쓰지 않고 `BALANCE.difficulty`
두 값으로 조인다.

| 값 | 하는 일 | 지금 값 |
| --- | --- | ---: |
| `hpGrowthBonus` | 각 장 `hpGrowth` 에 **더한다**. 1파는 그대로, 뒤로 갈수록 벌어진다 | 0.005 |
| `bossHpMul` | 장수(elite/boss) 체력. 각 장 `inserts` 의 배율 위에 다시 곱한다 | 2 |

곱이 아니라 합인 이유: 장마다 `hpGrowth` 가 0.078~0.26 으로 제각각이라 배수로 올리면
이미 가파른 1장만 폭발한다. 합이면 어느 장이든 "웨이브당 +0.5%p" 라는 같은 크기다.
`waves.ts` 가 웨이브 번호를 아는 유일한 자리라 가산은 거기서 하고(래칫 바닥에도 같이),
`Enemy.init` 은 잡몹에 `enemyHpMul`, 장수에 `bossHpMul` 을 나눠 곱한다.

**각 장이 이미 벼랑 끝이라는 것**이 이번에 드러났다. 전역 가산치를 +0.005 만 얹어도
2장은 12파, 6장은 13파에서 기준 플레이가 무너진다(두 장 다 자기 표 주석에 그 포화점이
적혀 있다). 그래서 그 두 장은 자기 `hpGrowth` 를 같은 양만큼 내려 유효 기울기를 지키고,
상향은 다른 자리로 돌렸다.

| 장 | 잡몹 | 중간 장수 | 최종 장수 |
| -- | --- | --- | --- |
| 1 | +0.5%p/파 | x2 -> **x4** | x3 -> **x6** |
| 2 | 그대로 (0.115 -> 0.110 + 가산치) | x2 -> **x2.5** | x3 -> **x3.5** |
| 3 | +0.5%p/파 | x2 -> **x2.5** | x3 그대로 |
| 4·5 | +0.5%p/파 | x1 -> **x2** | x1 -> **x2** |
| 6 | 그대로 (0.098 -> 0.093 + 가산치), 14·15파 hpMul 1.5/1.25 -> **2.6/2.25** | x1 -> **x2** | x1 -> **x2** |

**장수 배율에는 장마다 상한이 있다.** 장수는 2초마다 성벽을 치므로(위 절) 체력을 올리면
"성문에 붙는 순간 패배"로 곧장 뒤집힌다. 2장 여포는 3.5배, 3장 원소는 3배가 상한이다 —
원소 6배는 궁노/벽력거 도배, 조기 소집, 계략 두 정책까지 다섯 조합 전부 15파에서 졌다.

기준 플레이(`npm run sim` 권장 조합) 실측, 성 체력:

| | 1장 | 2장 | 3장 | 4장 | 5장 | 6장 |
| --- | --- | --- | --- | --- | --- | --- |
| 이전 | 992/1000 | 502/600 | 254/500 | 686/1020 | 613/1260 | 1345/1360 |
| 지금 | 959/1000 | 398/600 | 154/500 | 267/910 | 196/1260 | 609/1360 |

더 올릴 때는 `hpGrowthBonus` 를 0.001 씩 움직이고 `tests/level02·level03·level0456` 의
출력으로 확인한다. 3장은 여유가 가장 적다 — 슬롯 4기로는 이제 15파의 원소를 못 끊는다.
